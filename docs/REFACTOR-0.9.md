# 0.9.0 重构分析与回归说明

基于 0.8.1（0927142）。目标是让启动、编辑、保存、应用、停转和退出都能从界面直接理解，同时保留已验证的硬件访问边界。

## 问题与改动

| 旧行为 / 问题 | 0.9.0 行为 |
|---|---|
| EXE 位于 app/bin，运行依赖文件夹结构，文档建议用 CMD | 单个 EXE 内嵌模块、第三方许可证及对应源码；双击即可启动，普通启动不应用手动设置 |
| 曲线模式仍显示一大片灰色百分比与 RPM 控件 | 每次只显示所选控制方式的编辑区，曲线在主窗口直接预览 |
| 0 RPM 容易被当成读数故障 | 明确区分系统停转、按设置停转、等待起转、减速中、运转中；失联显示 -- |
| 保存和应用难以区分 | “仅保存配置”与“保存并应用”；实际运行状态始终放在顶部 |
| 保存失败仍继续下发手动命令 | 保存失败就停止应用；保留上次运行模式 |
| UI 中混合布局、状态描述和测试；配置模型依赖窗口的解析函数 | 拆分 MainForm.Layout、Presentation、MainForm.Shutdown、MainForm.Tests；CurveFormat 独立于窗口 |
| 退出循环使用 DoEvents + Sleep，容易重入 | QUIT 后由定时器异步等待确认，等待期间 UI 保持响应 |
| 已退出后台仍可能留下短暂“可应用”状态 | 同一过期门限控制显示与按钮；后台退出立即清空有效状态 |
| UAC 被取消、没有创建控制后台也可能触发恢复警告 | 没有启动后台时直接退出；曾请求手动调速的会话必须确认恢复，否则提醒 |
| 工作目录与配置/日志绑定，移动 EXE 后找不到原配置 | 数据独立存放在 LocalAppData/RedmiFanControl，支持同目录旧配置迁移且不覆盖已有新配置 |
| 再次双击只提示“已运行” | 唤回已有 0.9 主窗口，避免重复启动；0.8 仍提示从托盘打开 |
| 高 DPI 下直接按固定坐标布局可能裁切字体 | 系统 DPI 感知，全部控件构建后统一缩放；小窗口可滚动，已检查本机 200% 预览 |

## 架构边界

- `MainForm.Layout.cs`：布局、模式编辑区域、设置与关于。
- `MainForm.cs`：用户事件、连接、轮询、命令发送和读回确认。
- `Presentation.cs`：实时/过期判断、风扇状态、运行提示，纯逻辑可离线测试。
- `MainForm.Shutdown.cs`：异步退出与同会话自动恢复确认。重连也检查恢复状态。
- `Configuration.cs` / `CurveFormat.cs`：持久化、校验、旧配置迁移，不依赖窗口。
- `AppPaths.cs` / `RuntimeModules.cs`：可写数据路径、内嵌资源释放、SHA-256 校验。
- `ControlPolicy.cs`、EC 读写白名单、工作进程和独立看护继续承担硬件控制。

模块由普通权限 UI 准备；提权的硬件进程仅验证并读取。官方 PawnIO 驱动仍需用户从官网安装，EXE 不内嵌驱动安装器，不绕过 UAC。

控制规则仍为 60°C 输出下限、80°C 满速、95°C 恢复自动；允许停转、配置的最低输出、真正失速检测和独立看护仍保留。本次不重新探测或修改 EC 寄存器。

## 回归范围

离线测试覆盖：模拟 EC 协议及写地址限制、升温/降温规则、停转与失速、配置备份和迁移不覆盖、模式切换与应用命令、停转/断连呈现、缺失温度清空、异步 QUIT、拒绝外来/手动恢复状态、内嵌模块校验和损坏修复。

发布检查将 ZIP 解压后运行自测，并另将 EXE 单独复制到空目录运行同样自测。测试目录与真实配置、登录自启项、硬件会话隔离。CI 同时校验 EXE 和 ZIP 的 SHA-256。

上述回归不等同于真实高温、实际停转或看护进程故障注入验证。旧版正在调速时，应先通过其“×”或退出正常恢复自动，再运行新版。
